## Local format

Entries are indexed by `{module}-{book}-{test}` and have explicit `book`, `test`, `module` fields. `answers` maps question numbers to arrays of verified accepted strings. `parts[section].questionNumbers` maps each answer to its part, while `sources` records that part's source URL. A part may also contain `groups`: each group has `questions` and `acceptedSets`, preserving each verified unordered answer set separately. Never mix choices from separate alternative sets.

For a newly verified part, prepare a JSON object with `book`, `test`, `module` (`reading` or `listening`), `section`, `sourceUrl`, `answers`, and optional `groups`. Use:

```
node scripts/save-cambridge-answer-key.mjs path/to/verified-part.json
node scripts/audit-cambridge-answer-keys.mjs
```

The save command validates question membership against the existing imported part, merges only into the separate key store, and writes via a temporary file followed by rename. Identical replays are harmless. It rejects changes to any existing answer or group, including changed alternatives; review conflicting source evidence manually instead of overwriting a verified key. Run a single writer at a time. The command trusts the supplied answers have been verified against the source; it cannot certify that factual verification itself.

## Comparison behavior and checks

The existing `answer-review.mjs` normalizes Unicode compatibility characters, surrounding/repeated whitespace, and letter case. It does not strip articles, punctuation, words, or infer synonyms. Missing keys produce `pending`, displayed as **Not checked**. Known blanks display **Unanswered**. All selected choices must match a verified set regardless of order; extra or missing choices fail the match. Explicit alternative sets cannot be mixed. There is no IELTS band calculation.
